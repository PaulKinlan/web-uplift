# ADR 0003: Preserve source-test fidelity and make generated-tree updates readable

- **Status**: Accepted; the `nz68` half is implemented in `install-surface.mjs` (web-uplift-c6i1), the other two in their fixture writers
- **Date**: 2026-10-13
- **Related beads**: `web-uplift-qmku` (decision), `web-uplift-c6i1` (implementation proposal), `web-uplift-nz68`, `web-uplift-lql5`, `web-uplift-vubz`
- **Scope**: Tests and tooling sharing one worktree; no gate-selection or concurrency change.

## Context

Three independent collisions exposed one boundary. `lql5` created a temporary `.mjs` under the real repository root while `testSyntaxChecks` walked it; it was correctly fixed by moving the fixture writer to an OS-temp shim, preserving the real imports under test. `vubz` created a symlink cycle inside the real vendored schema directory; moving that fixture would stop testing the installer against the real path, so the observer was correctly changed to `lstatSync` and skip symlinks (measured 143 `.mjs` paths before and after). `nz68` records a third exposure: a sampler at 250 ms observed counts of 143 and 117, including six disappearing `.web-uplift/runner/*.mjs` paths, while generated vendored directories were rebuilt. The syntax test enumerates paths and reads them later in a child; a deletion between those operations can fail with ENOENT. These are failures of sharing a mutable root, not grounds to surrender the measured `--test-concurrency=6` or weaken affected-only fast-gate selection.

The source call graph refines the third diagnosis. `npm test` and `npm run test:fast` first call `tests/cdp-copy-sync.mjs --sync`: on an **existing, identical** vendored tree, that script compares bytes and does **not** remove directories. It calls `generateVendoredSurface()` only when `.web-uplift/` is absent; otherwise it writes individual **drifted** files without deleting a directory. The unconditional remove-and-recopy is in `install-surface.mjs:generateVendoredSurface`, called by the `prepare` lifecycle (`package.json`) and by the sync command on a missing tree. Tests invoke `npm pack` through `tests/test-helpers.mjs:packTarball()`, which in turn invokes `prepare`; consequently even a single full gate can overlap a `prepare` writer and the syntax reader in separate suite processes. The observed disappearing files prove exposure to a directory rebuild, but the sampler alone cannot attribute which invocation rebuilt it. Do not fix the wrong entry point on the assumption that every sync deletes files.

## Decision

**Put a fix at the side that can move without falsifying the test's subject, then require an explicit coverage equivalence argument for any observer narrowing.** For `lql5` that is the fixture writer; for `vubz` it is the observer, because symlink recursion is not part of a source-file census and the fixture must inhabit the real path. For `nz68`, keep a populated generated tree readable across normal regeneration: replace destructive directory remove-and-recopy in `generateVendoredSurface` with destination-safe staged file updates (temp sibling plus rename, after the existing symlink and tracked-edit refusals), reconcile removed source entries deliberately, and retain the byte-identity guard. The implementation must specify the initial-empty-tree and stale-file windows and prove the normal populated-tree case under a controlled concurrent writer and reader. Do not turn a transient ENOENT into a silently skipped source path; genuine missing paths and incomplete generation remain failures. Do not introduce a repository-root lock that serializes entire test suites or lower concurrency without paired speed measurements and a coverage proof.

Skipping `.web-uplift/` in the syntax census is **not** the default fix. Those `.mjs` copies currently contribute roughly 40 of the 139 paths recorded in `docs/speed.md`; simply excluding them tests fewer on-disk bytes and removes a way to catch a broken generation path. There is a possible future equivalence argument, not an assumption: the canonical source is parsed, the installer/guard derive the copy map from `install-surface.mjs`, every generated copy is byte-compared and missing/extra paths fail, and installed-package execution still runs. Any change to those premises needs explicit negative controls for corrupted, missing and extra generated `.mjs` files, along with a proof the comparison is stable against regeneration. No such change is authorized by this ADR. The affected-only fast gate must continue refusing unmapped executable paths and printing auto-mapped suites; changing its selection is outside scope.

## Consequences and verification limits

The proposed change is localized to the generator and its focused fixture/concurrency tests, but a stable **per-file** read is not a transaction across the whole tree: readers might see a mixture of old and new versions if the canonical source changes concurrently, and deletion of an obsolete generated path needs its own policy. Most fleet lanes have separate worktrees; the relevant same-worktree overlap here is gate, `npm pack`/`prepare`, and sync. The acceptance check is a deterministic interleaving of `prepare` against the actual `listFiles` plus delayed syntax read and copy guard, including changed/new/deleted sources, initial generation, symlink refusals, and byte identity; collect per-run path sets and failures rather than only a final exit code. Preserve the current gate speed budget (`docs/speed.md`), and compare focused timings before/after; no full gate is an architect deliverable.

**Population is not proven complete.** The evidence here is a static inventory of `package.json` lifecycle scripts; `tests/cdp-copy-sync.mjs`; `install-surface.mjs`; `tests/test-helpers.mjs:packTarball`; the `testSyntaxChecks`/`listFiles` caller; and the prior 200/250 ms root samplers recorded on `vubz`/`nz68`. That inventory catches the known filesystem producers and reader but cannot see dynamically assembled paths, unknown agents operating in the same worktree, changes under ignored `.web-uplift/` when a scanner reports only untracked-and-unignored entries, or a transient shorter than the sampling interval. A deterministic write/read interleaving test closes the *specific* known window; it cannot prove that no other root writer exists. Future root-writing fixtures should be moved outside the repo unless the real location is itself the behavior under test; reviewers should check this invariant on new fixtures and generators.

## Alternatives and reversal cost

- **Skip generated `.mjs` in the census:** smaller walk, but coverage changes immediately (roughly 40 copies on one measured tree). Reconsider only with the equivalence proof and negative controls above; the reversal cost is low for test code but high for trust if an unchecked broken copy ships.
- **Ignore or retry ENOENT in the observer:** masks a missing canonical path or a persistently incomplete generated tree; retries may turn flakiness into unpredictable gate latency. Reversal is a small edit, but evidence lost while enabled cannot be reconstructed.
- **Serialize whole suites, lock the worktree, or lower concurrency:** avoids some overlaps at a measurable throughput cost (the paired 14-suite medians were 66.2 s at concurrency 6 versus 82.6 s at 3), yet external `npm pack` may still run. Reversal requires new paired measurements and could strand gate capacity.
- **Generate in a separate throwaway package/worktree:** strongest run-wide isolation but changes package preparation, source fidelity, and pack tests across several modules; consider if per-file atomic publication proves insufficient. Reversal is a multi-file lifecycle migration, not a one-line gate change.
